Тестовое задание: инвентарь и предметы 

Стек 

- Node.js + TypeScript.


Описание задачи 

Смоделировать серверную часть системы предметов: у игроков есть инвентарь, предметы можно выбрасывать «на землю» в общий мир, подбирать и использовать. Разные типы предметов ведут себя по разному.

Мир и абстракции 

- Игрок — это минимум id и позиция { x, y } (числа).

- «Рядом» — расстояние между позициями не больше настраиваемого радиуса.

- Время идёт шагами tick.

- Операции с хранилищем инвентаря и предметов асинхронны (возвращают Promise) — считай, что за ними внешняя БД.

Требования 

Ядро системы 

- Единый модуль-источник правды: инвентари и предметы на земле хранятся и управляются в нём.

- Выброшенный предмет появляется «на земле» на позиции игрока и доступен игрокам рядом.

- Подобрать предмет может любой игрок рядом.

- Предметы на земле не живут вечно — исчезают по истечении настраиваемого времени.

- Добавление нового типа предмета не должно требовать изменения ядра.

Типы предметов 

Каждый тип декларирует своё поведение через обработчики: onPickup, onDrop, onUse (те, что нужны типу). Эффект onUse меняет состояние игрока - это и есть наблюдаемый результат.

Стакающиеся предметы (количество в слоте) — на твой выбор, если это уместно для типа.

Состояние игрока 

У игрока есть простые числовые характеристики, например health и armor (0..100), и при необходимости набор выданных предметов/патронов. Эффекты предметов меняют их — по этим изменениям и проверяется use.


API 

Минимальный серверный API:

giveItem(playerId, itemType, amount?)

dropItem(playerId, itemId)

pickupItem(playerId, groundItemId)

useItem(playerId, itemId)

getInventory(playerId): IItemInstance[]


Предметы для реализации 

Реализуй 4 из списка на свой выбор:

1. medkit — use восстанавливает health до настраиваемого максимума.

2. armor — use поднимает armor.

3. bandage — use лечит понемногу несколько тиков подряд (эффект во времени).

4. ammo — use добавляет патроны в состояние игрока.

5. flare — выброшенный «подсвечивает» игроков рядом на N тиков (пометка в их состоянии), затем эффект спадает.

6. repairkit — use чинит ближайший к игроку объект (смоделируй простой объект с полем health).

Требования к реализации 

- ООП-подход, читаемая структура. Ядро отделено от способа ввода (тесты/CLI) и от слоя хранения.

- Не использовать глобальные переменные.

- Все значения (эффекты, радиус подбора, время жизни на земле, задержки хранилища) — конфигурируемые.

Как проверить (обязательно) 

Приложи способ прогнать логику. Как минимум покажи: drop - pickup, исчезновение предмета по таймауту, эффект use, и конкурентный подбор одного предмета двумя игроками.
