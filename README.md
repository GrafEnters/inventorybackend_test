## Принятые решения

Раздел ведётся по ходу работы: часть решений уже реализована, часть — запланирована.

### Сборка и запуск

- TypeScript компилируется `tsc` в `dist/`, `npm start` собирает проект и запускает `dist/main.js`.
- Модули — ESM (`"type": "module"`, `module: nodenext`), поэтому в относительных импортах указывается расширение `.js`.

### Время

- Время идёт тиками: `GameLoop` на `setInterval` со счётчиком тиков, интервал задаётся параметром.
- Цикл можно запустить и остановить из кода — это нужно для тестов, где процесс не останавливают через Ctrl+C.

### Игрок

- Игрок: `id`, позиция `{ x, y }`, `health`, `armor`, патроны.
- `health` и `armor` всегда в диапазоне 0..100. Этот инвариант обеспечивает класс `NumberInRange`: значение зажимается в границы, `NaN` приводит к ошибке.
- Снаружи характеристики только читаются, менять их можно только методами игрока. Позиция отдаётся копией.
- Игроки — это «онлайн»-игроки: сервер стартует без игроков, они подключаются по ходу работы (id известен из авторизации, она вне рамок задания) и хранятся в памяти в `Map` по id.
- Инвентарь привязан к `playerId` и лежит в хранилище, поэтому переживает выход игрока: при повторном подключении с тем же id игрок получает свой инвентарь.
- Отдельной проверки «онлайн» нет: игрок онлайн, если он есть в реестре онлайн-игроков. `giveItem` и `getInventory` работают с инвентарём по `playerId`. Операции, которым нужен сам игрок (позиция, состояние) — `useItem`, `dropItem`, `pickupItem` — берут его из реестра; если игрока там нет, операция отклоняется.

### Предметы

- Реализуемые типы: **medkit, armor, ammo, bandage** (bandage — эффект во времени, проверяет игровой цикл).
- **Тип предмета** — класс-наследник абстрактного базового класса. Он хранит поведение (`onUse` / `onPickup` / `onDrop`, все необязательные — тип реализует только нужные) и параметры эффекта. На каждый тип — один экземпляр обработчика.
- **Реестр типов**: ядро знает только базовый класс и находит обработчик по id типа. Конкретные типы регистрируются снаружи, при сборке приложения. Поэтому новый тип добавляется без изменения ядра (без `switch` по типам).
- **Экземпляр предмета** — данные: id экземпляра, id типа, количество. В хранилище лежат только данные, без поведения.

### Стаки и инвентарь

- Стакаемость — свойство типа: тип задаёт максимальный размер стака. Нестакающийся предмет — тип с максимумом 1, отдельной логики для него нет.
- Инвентарь — список экземпляров без ограничения ёмкости (фиксированной сетки с пустыми слотами нет). Один экземпляр — один слот.
- `giveItem` и подбор сначала дозаполняют существующие стаки этого типа, остаток уходит в новые слоты.

### Операции

- **drop** — выбрасывается весь стак. Предмет на земле: тип, количество, позиция и момент исчезновения.
- **pickup** — подобранный стак сливается с имеющимися, поэтому id подобранного экземпляра может исчезнуть.
- Предмет на земле сохраняет id экземпляра: `groundItemId` — это тот же id, что был у предмета в инвентаре. При подборе остаток, не влезший в существующие стаки, ложится в новый слот с этим же id.
- **use** — количество уменьшается на 1, при 0 экземпляр удаляется из инвентаря.
- Бессмысленное использование запрещено: например, аптечку нельзя использовать при полном здоровье. Предмет при этом не тратится, а использование отклоняется.

### Хранилище и конкурентность

- Хранилище «тупое»: только сохраняет, читает и удаляет записи (экземпляры в инвентаре, предметы на земле). Вся доменная логика (стаки, «рядом», эффекты) — в ядре. Так логика видна в коде, а хранилище легко заменить.
- Все операции хранилища асинхронные, с настраиваемой задержкой — имитация внешней БД.
- Хранилище содержит два вида записей:
  - **инвентарь по `playerId`** — список слотов (экземпляров предметов). Читается и записывается целиком; безопасность обеспечивает блокировка по игроку;
  - **предмет на земле** — id, тип, количество, позиция, момент исчезновения. Предметы на земле тоже находятся за асинхронным хранилищем, а не в синхронной памяти сервера, иначе гонка при подборе исчезла бы искусственно.
- Состояние игрока (`health`, `armor`, позиция, патроны) живёт в памяти сервера, не в хранилище.
- Операции (CRUD, без отдельной операции «проверить», чтобы не было гонки check-then-act):
  - инвентарь: прочитать по игроку, записать по игроку;
  - земля: добавить, прочитать по id, получить все (для исчезновения по таймауту), атомарно удалить с возвратом результата.
- Ядро зависит от интерфейса хранилища, а не от конкретной реализации. Реализация для проекта — в памяти, с настраиваемой задержкой.
- Атомарность отдельного вызова хранилища не делает атомарной операцию ядра: между `await` выполняется чужой код. Поэтому:
  - **подбор** защищён условной атомарной операцией хранилища «удалить, если существует, и сообщить результат». Кто первым удалил предмет с земли, тот его и получил, второй игрок получает отказ;
  - **изменения инвентаря** защищены блокировкой по игроку в ядре: операции над инвентарём одного игрока выполняются строго по очереди, без потерянных обновлений.
- Блокировка — очередь промисов по ключу. В очередь ставится вся операция ядра целиком (от первого чтения до последней записи), а не отдельные вызовы хранилища: очередь отдельных вызовов не спасает от чередования «прочитал, прочитал, записал, записал».
- Хранилище — приватная зависимость ядра. Тесты и CLI работают только через API ядра, поэтому обойти очередь снаружи нельзя.

### Запланированные улучшения

- **Пространственный индекс (сетка) для предметов на земле.** Сейчас поиск предметов в радиусе — линейный проход по всем предметам, O(n). Улучшение: делить мир на клетки размером с радиус и хранить предметы по ключу клетки, тогда запрос проверяет только свою и соседние клетки.

- **Оптимистичная блокировка (версионирование) инвентаря в хранилище.** Сейчас защита от потерянных обновлений держится на дисциплине внутри ядра: вся работа с инвентарём игрока выполняется в его очереди. Улучшение: у каждого инвентаря есть номер версии, чтение возвращает данные вместе с версией, а запись принимает прочитанную версию и выполняется, только если та всё ещё текущая. Иначе запись отклоняется, и ядро перечитывает данные и повторяет операцию. Тогда гонку «прочитал, прочитал, записал, записал» ловит само хранилище, даже если какой-то код обратится к нему в обход очереди.

### Ошибки

- Недопустимые значения аргументов (границы, `NaN`, размер стака) — `RangeError`.
- Для доменных отказов API (предмет не найден, игрок далеко, предмет уже подобран, бессмысленное использование) планируются свои классы ошибок.
